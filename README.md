# PARTY ROOM v2.1

スマートフォンとPCで、9種類のCPU対戦・オンライン対戦ができるゲームハブです。
GitHub → Railwayでデプロイします。設定は **[SETUP.md](SETUP.md)** を最初に読んでください。

UNOは標準の1枚出し・ドロー処理を実装。まとめ出し、ドローの重ね出し、+4自由、UNOボタン必須、順位モードは明示的な追加ルールです。公開マッチのUNOは標準のカード処理＋全員順位の共通設定で集まります。

将棋の通常の千日手はこのアプリでは引き分けとします。持将棋は合意による引き分けです。公式大会の立会裁定・入玉宣言点数制などは対象外です。
大富豪はこのアプリのルールセットで、身分に応じた次ラウンドの交換・縛り・階段は採用していません。
ポーカーは1ハンドごとの持ち点順位で、新しいハンドは1,000点から開始します。
ブラックジャックはラウンドごとにプレイし、保険・スプリット・賭け金はありません。「ダブル」は追加1枚で終了する操作です。すべてゲーム内の点数のみです。

## マルチプレイ

- ゲーム別公開マッチ。1人から検索でき、同じゲームの人だけで対戦。最大2人のゲームは2人で即時、ほかは最大10人または待機15秒で2人以上から開始。
- 招待コードのプライベートゲーム。ホストがCPUを追加して開始可能。
- 最大10人のパーティー。公開一覧／招待のみ、参加承認、招待、参加申請、リーダー移譲・退出操作。
- フレンド申請・承認・削除、オンライン表示、パーティー招待、参加申請、ブロック、チャットミュート。
- パーティー／個人／ゲームのテキストチャット。所属・フレンド関係・ブロックをサーバー側で検証。

Discord OAuth2ログインが必須。ID・表示名・ユーザー名・512pxアイコンを反映し、本人の `guilds.join` 許可で指定サーバーへ参加します。Secret・Bot TokenはRailwayの環境変数から読みます。
セッションはランダムトークンのHttpOnly Cookieで、保存側はSHA-256のハッシュ。OAuth stateは1回限り・10分、PKCE使用。OAuthのアクセストークンはログイン処理後に保存しません。

## v2.1：将棋の操作と見た目

- PCは盤を中央に大きく配置し、相手の駒台を左、自分の駒台を右へ。スマホ縦画面では上下へ配置します。
- 盤上の駒・持ち駒をドラッグできます。タップで駒を選び、次にマスをタップする操作も使えます。
- 選択中・ドラッグ中は、サーバーが認める合法な移動先だけを表示します。二歩・王手放置などの禁止手は候補になりません。
- 移動、捕獲した駒の駒台への移動、駒台からの打ち込み、成りの裏返しをアニメーション表示します。捕獲した成り駒は元の駒へ戻ります。
- 自分の手番を盤上の小さな表示と名前の縁で案内。王手は短い日本語コール5種類から再生します。
- 和室背景はイラスト調。琴・笛をイメージした自作の和風BGMを5曲、1分ごとに切り替えます。
- 設定のゲームボイスで王手の声もOFFにできます。BGM・効果音・声の音量は個別に調整できます。

## モバイルとサウンド

自動／縦／横の選択。横向きは端末を回転させず、iframeの寸法・向きを切り替えます。安全領域は外側で確保し、ゲーム内のタップ／ドラッグ座標も回転後の盤面に従います。
UNO手札は重ねて上隅を残し、枚数が多い時は段組み。自分の番に出せるカードへ黄色の縁を表示。タップで選択、ダブルタップ・中央ドラッグ・出すボタンで送信します。

UNOは従来の5曲を1分ごとに切替。他の8ゲームは各々5分のオリジナル曲で、60秒ごとに5つの展開が変わります。
各ゲームの背景・駒やカードの音を分け、リバース・スキップ・UNO・4色のコールは各5種類。BGM・効果音・ボイスのON/OFFと音量を分けています。音は最初のタップで開始します。
ホーム画面への追加はPWA対応で、ストア登録は不要です。

## ローカル実行

Node.js 22以上（推奨24）。

```sh
npm ci
npm run check
npm test
npm start
```

Discordの設定はSETUP.md参照。手元でだけ動作確認する場合は、`NODE_ENV`をproductionにせず、`DEV_AUTH=1 npm start` として開発用ログインを使えます。本番では開発用認証を使わずDiscordを設定してください。

`DATA_DIR`に単一プロセス向けのJSONスナップショットを一時ファイル経由で保存します。Replicas=1。Railway Volumeなしでは再デプロイでデータが消えます。将来複数台にする場合はDB・共有マッチ状態・Socket.IO adapterへ移行が必要です。
切断した人は30秒後からCPUが代行し、同じアカウントで再接続すると操作を取り戻せます。明示的に退出するとCPUへ引き継ぎます。

# UNO PARTY v1.6

スマホとPCで遊べる、UNO風のオンラインカードゲーム。
GitHubに入れてRailwayで動かせます。ゲーム画面と対戦サーバーは同じサービスです。

## 今回の更新（v1.6）

- **レッド・ブルー・イエロー・グリーン・リバース・スキップ・UNOを各5種類、計35種類**。音声を新規に合成し、声色・速さ・語尾の違う5つの言い方を用意しました。5種類をランダム順で一巡し、同じ種類が連続しないように再抽選します。
- 旧版のMei/HTS音声から、Kokoro-82Mを使ったニューラル合成へ変更。ゲーム用の混合声色と演出ですが、学習モデル自体をゼロから作ったものではありません。開発時の診断通信は初期化前に無効化。ゲームは完成済みMP3のみ再生し、音声生成サービスやモデルの通信は不要です。
- **スキップを出した時の声**を追加。カード・ドロー・リバース・スキップ・ワイルド・警告・勝利・着地の効果音にも、各5パターンの変化を付けました。手番開始・メニューの音は追加せず、ボイス中のBGM低下は従来どおり8%まで。
- サウンド設定に7種類それぞれの試聴ボタン。タップのたびに別の言い方を確認できます。
- **ホームとゲーム設定に「自動・縦・横」**を追加し、端末に保存。横を選ぶと端末を傾けなくても画面自体を回転して横UIになります。縦を選ぶと、端末が横向きでも縦UIを使えます。
- iPhone 16e（390×844）・16（393×852）相当の画面と、上下の操作できない領域を考慮して調整。実際の端末ではセーフエリアに合わせて画面を収めます。
- 横向きホームは専用配置へ変更。ルーム・手札を保ったまま向きを切り替えられます。ドラッグ・ダブルタップ・カード演出も、切り替えた画面内の座標で動作します。
- +4の自由使用、自動受取、UNO必須、立体UNOボタン、PWA、BGM5曲と背景の1分交代、最後の1枚の叩きつけ演出は継続。

## すでに旧版を公開している場合

1. このZIPを解凍する。
2. 中身をGitHubの同じリポジトリに上書きしてCommitする。
3. Railwayの再デプロイ完了を待つ。自動デプロイOFFの場合はRedeployする。
4. スマホで公開URLを再読み込みして「音ありで遊ぶ」をタップ。

**public/assetsフォルダも必ずアップロードしてください。**
BGM5曲・ゲームコール音声・画像アイコン・テーブル背景が入っています。設定値は旧版と同じで使えます。

## ホーム画面に追加する（App Store・Google Play不要）

GitHubに更新版を上書きし、Railwayの再デプロイ後に**公開されたHTTPSのURL**を開きます。ZIPを端末で開くだけでは起動できません。

**iPhone**

1. Safariでゲームの公開URLを開く。
2. 共有メニュー →「ホーム画面に追加」。
3. 「Webアプリとして開く」が表示されたらONにして「追加」。
4. 次回からホーム画面のUNO PARTYアイコンをタップ。

**Android**

Chromeで公開URLを開き、ゲームの「ホーム画面に追加」から「アプリを追加する」。
ボタンが表示されない場合はChromeのメニュー →「アプリをインストール」または「ホーム画面に追加」を使います。
Chrome・EdgeのPCでもブラウザのインストール操作に対応します。

これはブラウザ技術を使ったPWAです。対応ブラウザではアドレスバーのない独立した画面で開けます。
対戦には通信が必要です。追加はロビーで済ませ、次の対戦からホーム画面のアイコンで始めてください。
更新は同じRailwayサービスへ再デプロイし、アプリを開き直します。インストール案内はホーム画面とゲーム設定から開けます。

## 初めて公開する場合

1. GitHubに新しいリポジトリを作成し、ZIPの中身をアップロードしてCommitする。
2. `package.json`・`package-lock.json`・`Dockerfile`・`railway.json`が一番上にある状態にする。
3. Railwayの `New Project` → `Deploy from GitHub repo` → そのリポジトリを選ぶ。
4. デプロイ完了を待つ。Builder・起動コマンド・Healthcheckはファイルで設定済み。
5. サービスの `Settings` → `Networking` → `Public Networking` → `Generate Domain`。
6. 発行されたhttps://のURLを開く。友達にも同じURLを送れます。

| 項目 | 設定 |
|---|---|
| Builder | Dockerfile、自動判定 |
| Start Command | npm start |
| Healthcheck | /health |
| Replicas | 1 |
| PORT | Railwayの自動設定を使う |

BOT TOKEN・Discord・Supabase・外部APIキーは不要です。
Railwayの利用料は使用中のプランと使用量によります。

## 再起動後もルーム・手札を残す

1. このゲームのRailwayサービスにVolumeを接続する。
2. VolumeのMount Pathを `/data` に設定する。
3. サービスのVariablesに次の1つを追加する。

```text
DATA_DIR=/data
```

4. 再デプロイする。

Volumeがなければ、Railwayの再起動・再デプロイで保存が消える場合があります。
接続が切れても、同じ端末の同じブラウザ・アプリで戻ると、自分の席と手札を復元します。
全員切断中は対戦を一時停止。最後の更新から24時間経ったルームは自動削除します。
端末の保存データを削除した場合は、元の席に戻れません。

## 遊び方

- 左上のアバターで名前とアバターを設定。
- **クラシック**：人数とルールを選び、CPU相手にすぐ対戦。
- **友達と遊ぶ**：「部屋を作成」でルームを作り、招待リンクか6文字のコードを共有。
- 空席にはCPUを追加可能。「CPUで空席を埋める」で一括追加。
- 同じ色・数字・記号のカードを選択し、中央へドラッグするかダブルタップで出す。出せなければ山札から1枚引く。
- ワイルドは色を選ぶ。7枚交換ONなら、7を出す時に相手を選ぶ。
- 自分の手札が2枚になったら、自分の番に **UNO!を押してから** 1枚出す。押すまで出せません。
- 手札は大きめで重ねて表示。枚数が多い時は段数を増やし、必要な場合だけ少し小さくします。
- 2vs2は向かいの席が味方。画面にTEAM 1／TEAM 2を表示します。



## アイコンを写真・画像にする

ロビーのプロフィール、または対戦中の自分のアイコン →「写真・画像を選ぶ」→「保存」。
端末内で512×512に中央切り抜き・縮小し、高品質WebP（非対応時JPEG）で同じルームの相手に共有します。以前保存した小さい画像は、元の写真を選び直すと更新できます。
元の写真はサーバーへ送らず、縮小した画像だけをルームの保存データに入れます。

## 山札と抽選

108枚（各色25枚、ワイルド系8枚）の共通の山札を、Node.jsのcrypto.randomIntを用いたFisher–Yatesでシャッフルします。
配札は1枚ずつ全員へ7周。ドローは山札の次のカードをそのまま消費します。
人間・CPU・難易度・ほしい色で当たり外れを変える処理はありません。
6000回の先頭カードの集計と、500回の4席の配札検証を追加しています。
希望色を必ず引ける保証はなく、残っているカードの内訳によって確率は変わります。

## 画面の向きを手動で変える

ホームの「画面の向き」、または対戦中のゲーム設定から選びます。
「自動」は端末に合わせ、「縦」「横」は選んだ向きに固定します。設定は次回も残ります。
手動の横画面ではUI全体が90度回転します。センサーによる画面回転ロックを解除する必要はありません。

## CPUの強さ

クラシックの開始前、または待機ルームの「ルール設定」から選択します。対戦中は変更できません。

| 設定 | 動き |
|---|---|
| かんたん | ランダムなカードと色を中心に選択。時々1枚引き、UNOの指摘も控えめ |
| 普通（初期値） | 単純な色合わせを基本に、カードの選択を適度にランダム化 |
| 強い | 手札の色・記号と相手の公開されている枚数を見て判断。相手のUNOを止めやすい |

全レベルとも同じ配札とルールです。CPUは他プレイヤーのカード内容を見て選びません。

## スマホで音が聞こえない時

1. 公開URLをSafariなどのブラウザで開く。
2. 「音ありで遊ぶ」、またはスピーカーボタン →「音を開始」をタップ。
3. BGM・効果音・ボイスをONにし、各音量が0でないことを確認。
4. 「音をテスト」で3音、「ボイスをテスト」でゲームコールを確認。端末の音量ボタンも上げる。
5. 別のアプリから戻って無音になったら、もう一度画面をタップする。

音楽・効果音はこのプロジェクトで制作。ボイスはニューラル合成で新しく生成し、ゲーム用に調整した同梱MP3です。端末の日本語読み上げの有無には依存しません。素材の出典・ライセンス・加工内容はASSETS.mdに記載しています。
音声の自動再生はブラウザによって制限されるため、最初のタップが必要です。
対応するiPhoneでは音声セッションをplaybackに設定し、Web Audioの中断からも復帰します。
非対応ブラウザ向けにも、BGMは通常のMP3再生を使います。
iPhoneのBGM音量は、端末の音量ボタンでも調節してください。
実機の音声出力は端末・ブラウザ・出力先の設定にも依存します。

## 採用ルール

- カード108枚。各ラウンドは数字カードから始まります。
- スキップは次の人を飛ばし、リバースは順番を逆にします。2人ならリバースもスキップ扱い。
- +2／+4は次の人へ自動で配ってお休み。スタッキングONで同じ+2／+4を持つ場合のみ、4秒以内に重ね返せます。出さなければ自動受取。
- +4は現在の色のカードがあっても使えます。選んだ色が次の場の色になり、+4のチャレンジはありません。
- 7枚交換：7を出す時に、相手を選んで手札を交換。
- 0–7：7で交換、0で手札を全員まとめて現在の進行方向の次の人へ渡します。
- 最後のカードが7・0なら、そのまま上がり。交換の後に手札1枚となった人は自動でUNO扱い。
- 強制プレイ：引いたカードが出せる時は、パスできません。時間切れ時は自動で出します。ただし必須UNOが未宣言なら、勝手に宣言・プレイせずパスします。
- UNOは残り1枚になる前に必須。旧版から復元した未宣言の1枚手札も、宣言するまで出せません。旧版の未宣言状態への指摘は次の人が出すか引くまでで、2枚ドローです。
- ターン時間切れは1枚引いてパス。ドローが溜まっていればその枚数を引きます。
- 2vs2は座席1・3と座席2・4がチーム。どちらかが上がるとチームの勝ち。
- 制限時間で終わる時は、手札の合計点が少ない人が勝ち。同点なら手札の枚数、それも同じなら引き分け。
- チーム戦の時間切れは、2人の残りカード点数の合計で判定。同点は引き分け。
- 数字は数字の点数、記号は20点、ワイルドは50点。勝者に相手の残りカード点を加算。
- チーム戦では、相手チームの残り点数を味方2人それぞれに加算します。
- 最後のカードが+2／+4の場合も、相手が引いてから得点を集計します。
- 通信切断が30秒続くとCPUが代行。戻ると操作を引き継ぎます。

## ローカル起動・テスト

Node.js 22以上、推奨24。

```bash
npm ci
npm start
```

http://localhost:3000 を開きます。

```bash
npm run check
npm test
```

102項目のテストに、基本ルール・追加ルール・320試合のCPUシミュレーション、
通信・再接続・再起動復元、UNO宣言の強制と偽装拒否、+4の自由使用と自動受取、抽選の分布、ドラッグ・ダブルタップ、
音声の中断と復帰、BGM音量、5曲の切り替え、最大108枚の収まり、アイコンの共有と保存、
PWAの追加操作・マニフェスト・PNGサイズ・オフライン画面・ライブ通信をキャッシュしない動作、
35種類の音声ファイル・一巡と連続回避・スキップの発火・選択した画面方向の手札の収まりが含まれます。
ブラウザでもiPhone 16e相当390×844（上下47/34pxを除外）、iPhone 16相当393×852（上下59/34pxを除外）の4人・20枚表示、
縦横の手動切り替えと回転後のドラッグ、375×667の20枚表示、タップ選択・ダブルタップ・中央へのドラッグ、UNO宣言前の拒否と宣言後のプレイ、勝利への遷移を確認しています。
iPhone実機のスピーカー出力を自動確認するテストではありません。
